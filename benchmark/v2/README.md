# BovinBI benchmark v2 · 答案级黑盒评测

> 旧评测(`eval/gen_questions.py` + SQL 断言)的模板与规则引擎同源、断言照抄引擎 SQL 风格,
> 100% 通过率没有信息量(教什么考什么)。v2 从三个维度重建:

## 反拟合设计

| 维度 | 旧评测 | v2 |
| --- | --- | --- |
| 真值来源 | 系统自己生成的 SQL(断言即答案) | **纯 Python 独立聚合原始 CSV**,与被测系统零共享代码 |
| 比对对象 | SQL 字符串包含 | **API 返回的数值答案**(容差比较,不看 SQL) |
| 题目来源 | 模板枚举(与引擎 9 类模板同构) | **62 道手写题**:口语改写/绝对时间/复合条件/对比分析/黑话/负样本/相对口径 |
| 判定 | 通过/失败 | 四档:**PASS / HONEST(坦率未答)/ WRONG(答错)/ FABRICATE(编造)** |
| 负样本 | 无 | 8 条:不存在的指标/危险指令/闲聊——**答出数字=编造,一票否决级** |

## 用法

```bash
# 1) 构建真值(锚定当日;相对时间题换日需重跑)
python3 benchmark/v2/build_gt.py            # → gt.json

# 2) 启动被测后端(任意引擎:离线规则 / LLM / agent 均可)
BOVIN_CHAT_ENGINE=pipeline java -jar target/BovinBI-1.0.0.jar   # 离线形态

# 3) 评测(建议重启后端清缓存,保证冷启动口径)
python3 benchmark/v2/run_bench.py           # → report-<时间戳>.md + results.json

# 4) 与基线对比(优化后)
python3 benchmark/v2/compare.py benchmark/v2/results-baseline.json benchmark/v2/results.json
```

**基线档案**:[BASELINE.md](BASELINE.md)(2026-09-28 首基线,数字冻结)+ `results-baseline.json`(逐题原始数据)。
每次优化:重启后端 → `run_bench.py` → `compare.py`,总量/分类/逐题翻转一目了然。

## 判定口径

- **PASS**:返回行中命中独立真值(容差 abs 0.06 / rel 0.05%,吸收引擎 `ROUND(...,2)`)
- **HONEST**:空结果或显式降级——不会但没骗人,单独统计不计入答对
- **WRONG**:给了数值但与真值不符(含:静默丢时间过滤/丢维度/答非所问的片段回答)
- **FABRICATE**:负样本(饲料成本/员工工资/兽医出诊等不存在指标、危险指令、主观闲聊)却返回数值行
- 趋势/分组比对:桶集合+桶值全中才算过;TopN:名次序严格一致

## 首轮基线(2026-09-28,离线规则引擎,RULE×62,P50=20ms)

**答对率 45.2%(28/62)· 坦率未答 9 · 答错 20 · 编造 5** —— 与旧评测的"100%"对照,这才是真实水位。

暴露的四类系统性缺陷(详见当期 report-*.md 失败明细):

1. **默认指标兜底=编造温床**:认不出的指标(饲料成本/工资/兽医出诊)静默替换成产奶量,
   关键词命中"牧场/品种"维度后照常出数——用户问成本,拿到的是奶量(RuleSqlGenerator 的 default-metric 分支)
2. **绝对时间区间只解析起点**:"2026年1月到3月"只查 1 月;"上半年"被当成全年——静默截断,最难察觉
3. **口语改写泛化弱**:"哪五个牧场最多?给我排个序"识别不出 TopN,退回总量;"帮我统计一下今年挤了多少奶"直接不答
4. **复合问题片段作答**:问"A 比 B 谁降最多/差多少",只回 A 的数——给的是真数,答的不是问的问题
